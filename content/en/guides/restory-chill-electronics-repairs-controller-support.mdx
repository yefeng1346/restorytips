## Steam Deck is a separate status

The official launch material labels Steam Deck as Playable. Playable is useful platform information, but it is narrower than native input support: it does not describe the button layout, text readability, mouse-like repair interactions, vibration, or stable frame rate. Keep the Deck status as “Playable” and leave detailed behavior **Unconfirmed**.

Do not rewrite the status as Verified unless an official Steam label changes. Also do not claim that a controller works perfectly because the game boots on Deck. Platform compatibility and control quality are separate fields that should be updated independently.

The supplied research confirms none of those details.

The exact interaction for disassembly, cleaning, part replacement, and reassembly is also **Unconfirmed** from a controller perspective. The repair loop itself is confirmed, but the sources do not say whether every step has a dedicated controller action or falls back to cursor input. Avoid publishing a fixed button list until it is captured in-game.

## Native support and Steam Input are not the same

Steam Input can be discussed as a platform-level configuration layer only if the current client and device are tested. It should not be presented as evidence that the game has a native controller layout. Likewise, a community-created mapping does not establish official support, and a layout that works for navigation may still fail on a repair interaction.

For now, the safe page wording is: the store does not publish a complete controller-support statement or button layout; Steam Deck is Playable; detailed behavior is **Unconfirmed**. This is more accurate than linking players to an unverified mapping or promising that every controller handles the workbench.
